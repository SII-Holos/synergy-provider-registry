# Synergy Provider Registry

Signed provider model catalog for [Synergy](https://github.com/SII-Holos/synergy), distributed via GitHub raw CDN.

## Files

- `catalog.v1.json` — the provider catalog (version 1 schema). Edit this to change provider recommendations, fallback models, or model metadata.
- `catalog.v1.json.sig` — base64 Ed25519 signature over `catalog.v1.json`, regenerated by CI on every change.
- `scripts/sign.mjs` — the signing script used by CI.

## How clients consume it

Synergy clients fetch:

```
https://raw.githubusercontent.com/SII-Holos/synergy-provider-registry/main/catalog.v1.json
https://raw.githubusercontent.com/SII-Holos/synergy-provider-registry/main/catalog.v1.json.sig
```

and verify the signature against a public key embedded in the client before trusting the catalog. If fetch or verification fails, clients fall back to their local cache and bundled models.dev data.

## Updating the catalog

1. Edit `catalog.v1.json` (on a branch or directly).
2. Push to `main`. The `sign` workflow validates the JSON, re-signs it, and commits the updated `.sig`.
3. Clients pick up the new catalog within their cache TTL (default 1 hour).

Do not hand-edit `catalog.v1.json.sig` — it is CI-generated.

## Key management

The Ed25519 private key lives in the `CATALOG_PRIVATE_KEY` GitHub Actions secret. The matching public key is embedded in Synergy clients (`packages/synergy/src/provider/catalog.ts`, `DEFAULT_PUBLIC_KEY`). Rotating the key requires a client release.
